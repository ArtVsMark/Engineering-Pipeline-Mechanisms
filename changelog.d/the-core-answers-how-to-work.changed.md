### Ядро отвечает на «как работать» — состояние проекта выехало из него

**Назвал владелец:** «там должно быть как работать, а не планы работ и прочая
лабудистика... Чего в проекте ещё нет — зачем нам в AGENTS.md?»

**Замер по разделам ядра:**

| раздел | слов | про «как работать»? |
|---|---|---|
| **🕳 Чего в проекте ещё нет** | **748** | **нет — это состояние проекта** |
| 🎯 Открытая работа | 261 | да |
| ✅ Перед толчком | 247 | да |
| 🚦 Критические запреты | 202 | да |
| прочие пять | 59–164 | да |

**Треть ядра, втрое больше любого соседа** — и платило это каждое окно при
каждом старте.

**Половина раздела к тому дню ПРОТУХЛА.** Настоящих строк было восемь, четыре
из них объявляли отсутствующим уже построенное:

| строка заявляла | на деле |
|---|---|
| автоперезапуска мигнувшей на изменении нет | есть — `main_red.rerun_on_change` |
| способа открыть изменение задержанным нет | есть — трейлер `Ждёт:` |
| порога покрытия нет | есть — `scripts/coverage_floor.py` |
| код общих механизмов отложен | девять переиспользуемых шагов |

Три из четырёх закрыты в тот же день. Пока раздел лежал в своде, его читали —
но не перечитывали.

**Вынесено в [`docs/dev/gaps.md`](../docs/dev/gaps.md)** со своим читателем; в ядре
осталась врезка на пять строк. **Ядро: 2204 → 1494 слова**, запас налога на
старт вырос с **43 до 799**.

**ТРИ ПРАВИЛА ЭТО УЖЕ ЗАПРЕЩАЛИ, И ВСЕ ТРИ ПРОПУСТИЛИ** — потому что меряли
форму, а не предмет:

| правило | что держал гейт | почему пропустил |
|---|---|---|
| 029 | объём свода ≤ 2300 | 2204 < 2300 — зелено |
| 024 | нет раздела-летописи | это не летопись, а список «чего нет» |
| 021 | объявлен читатель | объявлен |

**Заведён признак, которого не хватало, и он БЕЗ рукописного числа:** раздел
свода ссылается на задачи не чаще, чем на правила каталога. Свод объясняет
ПРАВИЛОМ, состояние проекта — ЗАДАЧЕЙ. Порог вида «не больше трёх ссылок»
разошёлся бы с документом первой же правкой
([005](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/005-hand-written-numbers-rot.md));
здесь сравниваются две величины одного документа.

**Замер по всем семнадцати разделам обоих сводов:** задач 0–2 при правилах
0–10, отвергнут ровно один — тот самый раздел, 23 против 8. Предикат не шире
предмета
([195](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/195-a-narrowed-predicate-names-its-neighbour.md)).

**Вторую половину гейтом не взять** — «на какой вопрос отвечает раздел»
читается, а не считается. Её держит новый навык
`.claude/skills/rulebook-keeps-how-to-work`, и это объявлено, а не умолчано
([057](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/057-unmechanizable-rules-are-named-explicitly.md)).

**Проверено откатом:**

* раздел возвращается в ядро — краснеет `test_a_rulebook_explains_by_rules_not_by_tasks`;
* предикат ослаблен до счёта одних задач — раздел проходит, и ловит его уже
  только гейт объёма, то есть исходная дыра.

**Попутно снято ещё одно протухшее число:** свод окна писал «Семь навыков»,
когда их стало восемь.
