# Фрагменты журнала

> **Читатель:** тот, кто вносит изменение.

Журнал собирается **из фрагментов**, а не правкой общего файла
([030](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/030-changelog-from-fragments.md)).
Причина не в удобстве: два файла с разными именами не конфликтуют никогда, а
на конфликтном изменении площадка **не создаёт проверок вовсе** — то есть
общий файл журнала останавливает не только себя.

Вторая причина — качество записи. Запись, сделанная после выпуска, пишется по
памяти и описывает код вместо изменения для того, кто это потребляет.

## Имя файла

```
changelog.d/<что-изменилось>.<род>.md
```

`<что-изменилось>` — короткий слаг **по смыслу записи**, а не номер задачи.

**Номером называть нельзя, и это стоило потерянной записи.** Одна задача живёт
дольше одного изменения: `12.fix.md` завели дважды, и второй заход молча
переписал первый — запись об исправлении атрибуции исчезла без следа и без
выпуска. Файлы с разными именами не конфликтуют никогда, а два изменения,
целящие в одно имя, конфликта не дают тоже: побеждает последний. Поэтому имя
берётся от того, ЧТО изменилось, и слаг из одних цифр отвергает
`scripts/check_journal.py`.

`<род>` — один из:

| род | что означает | попадает в раздел |
|---|---|---|
| `contract` | меняется **поверхность контракта**: имена шагов, входы, имена контекстов, форма `.pipeline.yml` | Несовместимое |
| `added` | появилось новое поведение, поверхность не тронута | Добавлено |
| `changed` | поведение изменилось: договор, свод, витрина, порядок работ | Изменено |
| `fixed` | дефект: поведение расходилось с обещанным | Исправлено |
| `removed` | механизм или обещание сняты | Удалено |
| `internal` | для потребителя не меняется **ничего** | Внутреннее |

Род `internal` — это ответ «не нужно», и он **обязан назвать причину**
([154](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/154-none-must-name-its-reason.md)).
Форма задана, и **первой строкой** фрагмента идёт ровно она:

```
> **Потребителю безразлично:** <почему это его не касается>
```

Молчание состоянием не является. Форму держит разбор фрагментов
(`scripts/build_changelog.py`), а не внимание автора: пока правило жило одной
прозой здесь, оба внутренних фрагмента проекта открывались заголовком, и нашёл
это внешний взгляд, а не сборка
([002](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/002-rule-without-mechanism.md)).

## Что внутри

Одна-три строки о том, **что изменилось для того, кто это потребляет**, а не
что переписано в коде. Ссылка на задачу — в конце.

**Роды — те же, что у соседей по семье** (`added` · `changed` · `fixed` ·
`removed` · `internal`), плюс свой `contract`. Общий словарь нужен человеку,
который смотрит несколько проектов сразу: «feat» против «added» он иначе
переводит в уме каждый раз. Свой род один и с причиной: здесь версионируется
контракт механизмов, и несовместимое изменение поверхности обязано быть видно
отдельно, а не тонуть в «изменено».

**Имя файла — слаг по смыслу записи, а не номер задачи.** `2k.fix.md` не
говорит ни о чём: чтобы понять, что внутри, файл надо открыть, а при разборе
конфликта или сборке выпуска их три десятка. `unclosed-fence-eats-nothing.fixed.md`
читается с первого взгляда — так же, как у соседей по семье. Номер задачи от
этого не теряется: он стоит последней строкой внутри.

```markdown
Сводный гейт собирается опросом проверок на голове, а не через `needs`:
пропущенный агрегатор больше не засчитывается защитой ветки за пройденный.

#11
```

## Чего здесь не делают

- **не собирают `CHANGELOG.md` на каждом изменении** — сборка идёт при выпуске
  ([030](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/030-changelog-from-fragments.md)).
  Общий файл, который трогает каждая ветка, даёт конфликт на каждом втором
  изменении: ровно тот инцидент, из-за которого фрагменты и заведены. На
  изменении гейт спрашивает фрагменты, а не собранный файл;
- **не правят собранный `CHANGELOG.md`** — он производный, его переписывает
  сборка ([125](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/125-a-generated-file-is-not-a-store.md));
- **не пишут номер версии** — он берётся из `CONTRACT_VERSION`, единственного
  источника ([035](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/035-version-is-never-edited-by-hand.md));
- **не откладывают фрагмент** «до выпуска»: материал портится за дни.
