### Сводный гейт печатает состояние, на котором вынес красное

Разбор гонки в `ci_complete.py` стоил шести починок, и каждая начиналась
одинаково: красное есть, а состояние, по которому оно вынесено, уже другое.
12.09.2026 это повторилось трижды за вечер — заходы вынесли **решённое**
красное за полминуты при сроке 900 секунд, и один из них держал слияние на
полностью зелёной голове.

Разобрать их было нечем. Лог прогона читается **не из всякого окна**: облачному
хранилище закрыто прокси, аннотация давала только «Process completed with exit
code 1», а к моменту разбора голова уже другая.

Теперь заход печатает вместе с отказом **все записи каждого имени** — исход,
время, номер — и состав едущих джобов сводимого прогона. Не выбранную запись, а
все: выбор между ними и есть то, что разбирают, и показать один итог значило бы
скрыть предмет.

Вывод уходит не только в лог: прогон кладёт его в **сводку джоба** и в
**аннотацию**, а их отдаёт REST. Разбор задним числом становится возможен из
любого окна.

Это замер, а не починка самой гонки: чинить её по разбору, а не по прочитанному
— ровно то, на чём смена уже спотыкалась
([044](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/044-check-the-premise-before-fixing.md)).
Починка — следующим заходом, по первому же прочитанному состоянию.
