### Кнопка была у девятнадцати прогонов, а держал её список из десяти имён

События теряются. Если запуск бывает **только** по событию, единственным способом
добудиться становится мусорное изменение
([104](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/104-event-driven-automation-needs-a-manual-button.md)).

**Замер 18.09.2026:** прогонов в дереве **двадцать**, ручную кнопку несут
**девятнадцать**. Требование исполнялось — а держалось **списком из десяти имён**,
вписанным в ответ каталогу рукой. Список отстал от дерева почти вдвое и не краснел
нигде; новый прогон без кнопки не покраснел бы тоже.

Гейт требует кнопку у каждого прогона. **Исключение объявлено, а не угадывается:**
список разрешительный, и у каждого исключения названа причина, по которой кнопка
бессмысленна. Сейчас оно одно — прогон, отвечающий на **обращение** человека:
событие там и есть рука, а кнопка без обращения смотрела бы в пустоту.

**Обратная половина держится там же:** исключение не переживает свой прогон и не
прикрывает прогон, у которого кнопка есть. Мёртвая строка читается как решение о
том, чего нет, а лишняя — как запрет там, где запрета не нужно; оба состояния
молчат (154).

**Разбор знает обе формы записи `on`.** YAML читает голое `on:` как булево `True` —
это норма языка, а не причуда, и разбор, знающий одну форму, потерял бы **все**
события прогона молча (045). Тот же род, что закрывался часом раньше у разбора
вызовов.

Механизм ответа **поднят с внимательности до гейта**. В записи родов отмечено:
«число без способа замера» встречено **пятый** раз — и на этот раз породило гейт, а
не правку текста.

**Проверено откатом, три половины:** у прогона сняли кнопку — краснеет с именем;
исключение объявлено отпиской — краснеет; исключение пережило свой прогон —
краснеет.

**140**, **178** и **182** подтвердились без правок.
