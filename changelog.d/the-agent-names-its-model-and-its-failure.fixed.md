### Причина отказа взгляда найдена, и отказ больше не прячется в логе

**Почему `claude-opus-5-5` уронил взгляд.** Действие было закреплено на
`v1.0.216`, а оно ставит **Claude Code 2.1.261**. У CLI свой реестр моделей, и
в 2.1.261 имени `claude-opus-5-5` нет — есть `claude-opus-5`, `claude-fable-5-1`,
`claude-opus-4-8`. Проверено по самому бинарю из реестра npm: в 2.1.261 это имя
не встречается ни разу, в **2.1.280** — есть, с записью «Opus 5.5». Действие
**`v1.0.232`** ставит именно 2.1.280.

**Действие поднято до `v1.0.232`** во всех пяти вызовах. Входы и выходы
действия между версиями совпадают поимённо. Модель пока **не** объявлена: она
вернётся отдельным изменением, после того как живой заход на новой версии
покажет, что действие работает, — второй раз ронять взгляд на непроверенном
нельзя.

**Отказ захода больше не невидим.** После каждого из пяти вызовов стоит шаг
`scripts/agent_run.py`: он читает файл захода, который действие отдаёт и при
отказе, и печатает аннотациями проверки **модель захода** (из `system/init`) и
**текст отказа** (из итога с `is_error`). Аннотации площадка отдаёт обычным
чтением — их видит и человек в списке проверок, и окно через API; лог для
этого больше не нужен. Заодно проект впервые узнает, на какой модели идёт
взгляд по умолчанию (#663).

**Гейт:** у каждого вызова агента есть `id`, и за ним в том же задании стоит
шаг `agent_run.py` по его файлу захода — с `always()`, иначе после отказа он
не запустится.

**Форму файла захода разбирает один модуль:** `late_look.answer_of` теперь
берёт список сообщений у `agent_run`.

**Изменение уходит без внешнего взгляда** — оно правит `review.yml`. Первым его
проверит заход на следующем изменении: он же покажет модель умолчания.

**Проверено откатом:** шаг снят у одного вызова, `always()` снят, `id` снят —
гейт краснеет на каждом с адресом вызова.
