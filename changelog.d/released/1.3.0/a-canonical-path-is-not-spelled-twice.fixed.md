### Каноническое имя пути не пишется вторым литералом

**Нашёл внешний взгляд** (`10ca99d` на [#578](../../pull/578), вес «риск»):
`BUILT_JOURNAL` — третий по счёту литерал `"CHANGELOG.md"` в дереве, при том что
канон объявлен (`paths.CHANGELOG`), а модуль `paths` уже импортирует. Сам
`paths.py` документирует этот класс на примере `TRUNK`: три независимых
написания имени общей ветки разъехались молча.

**Замер по ВСЕМУ классу, а не по одному случаю.** Предикат «каноническое имя из
якоря, написанное строкой» назвал **одиннадцать мест, пять имён**. Но число
обмануло, и список прочитан поимённо:

| место | вердикт |
|---|---|
| `check_journal.py` — `BUILT_JOURNAL` | **дефект** |
| `check_version.py` — `ALLOWED` | **дефект**, и сразу ДВА канонических имени |
| `build_changelog.py` ×2, `release.py` — `"README.md"` | законно: сравнение по имени файла в каталоге фрагментов |
| `build_facts.py` ×3 — `"scripts"` | законно: ключ словаря фактов |
| `build_facts.py`, `check_new_is_tested.py` — `"main"` | законно: имя функции Python и точка входа модуля |

**Настоящих дефектов два из одиннадцати.** Число этого не показывало — показал
список имён
([195](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/195-a-narrowed-predicate-names-its-neighbour.md)).

**Второй дефект нашёлся рядом и сам по себе поучителен:** `check_version.py`
брал `paths.VERSION` для одной константы — и писал `"CONTRACT_VERSION"` строкой
для соседней, **четырьмя строками ниже**. Два написания одного имени в одном
файле.

**Заведён гейт**, а не только починка: сегодня третье написание ловил только
внешний взгляд, и поймал он его на четвёртом появлении
([002](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/002-rule-without-mechanism.md)).
Живёт он там, где уже стоит этот класс — `tests/test_settings_anchor.py`, гейт
единственного якоря настроек
([090](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/090-shared-helpers-move-up-not-sideways.md)).

**Предикат сужен ДВАЖДЫ, и оба сужения замерены, а не угаданы:**

* **сосед назван списком** — три имени, у которых совпадение письма ничего не
  значит (`README.md`, `scripts`, `main`), с причиной у каждого;
* **читается КОД, а не текст файла** — и это поймано на себе: первый заход искал
  строку во всём файле и **покраснел на собственном пояснении**, которое этот же
  дефект и объясняет. Назвать имя в комментарии — не то же, что завести второй
  источник. Разбор идёт через `ast`, докстроки исключены наравне с
  комментариями.

**Проверено откатом, каждая половина:**

* литерал возвращается в `check_journal` — краснеет;
* литерал возвращается в `check_version` — краснеет;
* исключение без причины — краснеет;
* проза снова читается как код — краснеет.

**Поведение обоих гейтов не изменилось:** значения совпали до знака, то же
принимают и то же отвергают.
