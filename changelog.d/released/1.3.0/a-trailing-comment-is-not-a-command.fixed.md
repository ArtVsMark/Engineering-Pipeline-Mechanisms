### Хвостовой комментарий больше не читается установкой

Разбор строки `run:` отбрасывал строку, **начинающуюся** с решётки, а
комментарий в хвосте оставлял. Из-за этого `pytest  # не забыть pip install`
читался установкой: маркер находился в пояснении, а не в команде, и рабочий
шаг объявлялся служебным — то есть его настоящее падение пряталось за
площадкой.

**Резать по первой решётке нельзя, и это замер, а не осторожность.** В дереве
**четыре** строки `run:` несут решётку внутри кавычек:

```
echo "замер отработал — ответ записан в #196" ;;
echo "смотрим названное: #$ASKED"
…и две соседних
```

Наивная обрезка искалечила бы все четыре. Предикат « #» назвал их поимённо — и
это ровно та причина, по которой имена читаются, а не только счёт
([195](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/195-a-narrowed-predicate-names-its-neighbour.md)).
Поэтому разбор ведёт `shlex`: он знает кавычки. Незакрытая кавычка ему не по
зубам — тогда строка отдаётся как есть, шаг считается работающим, и ошибка
уходит в дешёвую сторону.

**Снят выдуманный довод.** Рядом с разбором связок стояло «порядок значим:
`||` обязан проверяться раньше `|`». Проверено прогоном на обоих порядках —
результат тот же: пустые куски отсеиваются ниже. Довод звучал правдоподобно и
был неверен
([044](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/044-check-the-premise-before-fixing.md)).
Теперь это держит прогон, а не проза.

**Состав служебных на живом дереве прежний:** те же шесть имён.

**Проверено откатом:** комментарий остаётся командой — краснеет одна проверка;
режем по первой решётке без оглядки на кавычки — краснеет она же, на другом
утверждении.
