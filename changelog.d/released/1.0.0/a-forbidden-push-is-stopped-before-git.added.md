Запрет «не пушить в чужую ветку» перестал держаться вниманием: толчок мимо
головы теперь отвергается **до** вызова git.

Прежний ответ каталогу говорил: «предмет вне досягаемости — чья ветка, знает
человек». Ответ описывал не тот предмет. Признак «чужая» машине и правда
недоступен, а признак, которым пользуются все три соседа, доступен вполне: **имя
ветки в команде не совпадает с текущей головой**. Промах пальцем, строка,
скопированная из передачи, старое имя из прошлой смены — все три дают одно
наблюдаемое: содержимое уезжает не туда, куда смотрит окно.

Инцидент свой, сегодняшний: окно, стоя на `agent/items-sweep`, толкнуло в
`agent/marking-moves-out-of-the-queue`. Обе ветки свои, обе законные — а
следствие такое же, как у чужой: конвейер открыл **второе** изменение на ту же
работу (#116), закрывать его пришлось руками, и ветка осталась висеть, потому
что прав удалить её у окна нет.

Почему хук, а не гейт: конвейер видит артефакт, а не действие — к запуску
прогона толчок уже состоялся. Отвергать надо там, где это ещё возможно.

Границы:

- `HEAD:<другая-ветка>` **не** исключение: «своя голова под чужим именем» и есть
  форма этого инцидента. Первая редакция обещала обратное — обещание правилось
  под поведение, а не наоборот;
- общая ветка отвергается из любой головы;
- разбор идёт **по словам команды**, а не поиском подстроки: `git push` в теле
  записываемого файла — данные, а не действие (085). Составную строку
  `cd … && git push …` первая редакция пропускала — поймано проверкой;
- событие не разобралось — сторож молчит: ронять чужой инструмент из-за своего
  разбора хуже, чем пропустить команду (084).

Приём взят у соседей, файл свой: у них запреты свои и собраны под их конвейеры
(162).
