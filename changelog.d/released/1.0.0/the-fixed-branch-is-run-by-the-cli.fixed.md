Ветка, которую правила прошлая починка, теперь **гоняется заходом CLI**, а не
только юнит-тестом числа. Сам дефект воспроизводился именно так: `next_contract`
отдавала верное число, а пометку «НЕСОВМЕСТИМО» печатала `announce` — и проверка
числа его не видела.

Два случая рядом: `--breaking` без фрагментов поверхности говорит «версия не
меняется» и «двигать нечего», а с фрагментами — ставит пометку и называет новый
мажор. Без второго «пометка следует числу» держалось бы одним отказом, и
пропажа пометки вовсе выглядела бы как починка
([097](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/097-a-checker-has-two-error-types.md)).
