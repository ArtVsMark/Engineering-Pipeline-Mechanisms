### Сторож толчка: чего не разобрал — не пускает

Пять находок внешнего взгляда на [#181](../../pull/181), и все они об одном:
вчерашняя починка сторожа сделана наполовину, а в оставшейся половине повторена
та же ошибка, которую она же и правила.

**Обёртка со своими ключами проходила мимо.** Разбор требовал, чтобы команда
шла сразу за именем обёртки, и `env -i git push`, `nice -n 5 git push`,
`stdbuf -oL git push`, `env -u HOME git push` не виделись сторожем вовсе.
Пропуск «всего, что начинается с дефиса» тут не помогает: часть ключей несёт
значение (`-n 5`), и оно становится первым словом — то есть командой. Внутри
обёртки вызов git теперь ищется **сканированием**; на верхнем уровне
сканировать по-прежнему нельзя — там в словах законно живёт текст документа
(`cat > f <<EOF … git push … EOF`).

**Совмещённый ключ оболочки не распознавался.** `bash -lc "git push …"`,
`sh -xc "…"` — обычные написания, а искалось ровно слово `-c`. Ищется короткая
связка ключей, в которой есть `c`.

**Предел вложенности молча пропускал.** Исчерпав глубину, разбор отдавал
команду дальше — и это расходилось с фейл-клоузом, выбранным в том же изменении
для неузнанной головы. Теперь у сторожа три ответа вместо двух: «это толчок
вот туда», «это не толчок» и **«разобрать не удалось»**. Третий отвергает —
сторож не знает, толчок перед ним или нет, а «не знаю» здесь обязано значить
«не пущу». Незакрытая кавычка попала в тот же класс: прежде она отдавала тот
же ответ, что и безобидный `ls`.

**Граница `DEPTH` покрыта проверкой** — она и обнажала находку выше.

Фейл-клоуз не значит «отвергать всё»: разобранное и безобидное проходит —
`env -i ls`, `bash -lc "git status"`, `nice -n 5 python -c pass`.
