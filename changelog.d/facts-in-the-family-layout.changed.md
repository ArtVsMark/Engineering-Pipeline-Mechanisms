### Факты — по адресу и ключам контракта семьи

`facts.json` и значки публикуются в ветку `badges` по пути `.github/badges/`, как
у грейдера, каталога, токенов и глоссария, а не в корень ветки. Ключи — по
контракту фактов витрины семьи (`ArtVsMark/ArtVsMark` · `.rules/facts-contract.md`):
`schema` строкой `"1.0"` рядом с `schema_of`, `repo`, `generated_at` (ISO с
поясом) и `commit` вместо `generated`, `tests.functions` вместо `tests.total`,
`checks_per_pr` (`count`, `names`, `by_class`) вместо `checks`, `coverage_percent`
вместо `coverage.percent`. Переименовано, а не продублировано; свои разделы
(`contract`, `version`, `rules`, `family`, `scripts`) остались — незнакомые ключи
витрина игнорирует.

`checks_per_pr` считает только проверки ИЗМЕНЕНИЯ: прежний `checks` считал и
прогоны вне него, то есть на вопрос «сколько проверок на изменении» отвечал не
тем числом. `coverage_percent` отсутствует, если покрытие не прочитано: по
контракту отсутствие ключа — «не мерили». Без имени проекта (`--repo`) факты не
публикуются: это обязательный минимум контракта.

Свои читатели поправлены тем же изменением: `runs_series.py` (адрес и ключ
покрытия), адреса `where` в `.rules/showcase.json`.

**Значки README переезжают вторым шагом.** Ссылка на производное едет ПОСЛЕ
первого прогона публикации (`check_derived_refs`), а ветка `badges`
перезаписывается целиком. Поэтому до второго изменения прогон кладёт копию
значков и в корень ветки. Тем же вторым изменением README переходит на
`.github/badges/`, а копия снимается.

**Проверено откатом:** публикация в корень ветки, `schema` числом, время без
пояса, публикация без имени проекта, ноль вместо отсутствия покрытия, счёт обоих
разделов проверок — каждый краснеет своим случаем.
