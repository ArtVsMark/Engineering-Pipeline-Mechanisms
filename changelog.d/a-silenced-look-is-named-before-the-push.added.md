### Правка файла прогона глушит взгляд — и теперь об этом говорят до толчка

**Что происходило.** Площадка отказывает действию агента, когда файл прогона
расходится с общей веткой: «the workflow file must exist and have identical
content to the version on the repository's default branch». Шаг при этом
объявлен `continue-on-error`, поэтому остаётся **зелёным** — джоб зелёный,
ответа нет вовсе, и изменение уезжает в общую ветку непросмотренным. Узнавалось
это из реестра #89 уже после слияния.

**Замер 21–22.09.2026 по ста слитым изменениям:**

| | |
|---|---|
| файлов прогонов, объявляющих действие агента | **3** |
| изменений, трогавших такой файл | **2** |
| из них взгляд на голове изменения ответил | **0** |

У #563 ответ был — но от **позднего взгляда по общей ветке**, через семь минут
после слияния, где файл уже совпадал. Исключений в замере нет.

**Что теперь.** Предполётная перед толчком называет это автору: какой файл
тронут и чего не будет. Носители действия берутся **из дерева по строке
вызова**, а не перечисляются именами — их три, и четвёртый появился бы молча.

**Это предупреждение, а не запрет, и это выбор.** Правка такого файла законна —
иначе их нельзя было бы менять вовсе. Отказ запрещал бы работу, а не ошибку.

**Чего этот шаг НЕ делает.** Он не различает причину тишины после факта: это
предмет реестра #89, и там решено называть видимое, а не выбирать между
причинами. Прежняя попытка выбрать уже отменялась внешним взглядом на #180 —
здесь вопрос другой и задаётся раньше: не «почему промолчал», а «сейчас
промолчит».

**Три находки собственного прогона.** `git grep` отдаёт исход 1, когда ничего
не нашёл, — разбор считал это отказом; git экранирует не-ASCII путь
восьмеричными последовательностями, и имя файла было бы нечитаемым;
несуществующий каталог ронял запуск до кода возврата. Ни одну из трёх не видно
чтением.

**Для потребителя.** Свой проект получает то же бесплатно: признак —
строка вызова действия в `.github/workflows/`, и список именами вести не нужно.
