# 002. Ревью собирается из двух соседей, а не копируется у одного

> **Читатель:** тот, кто ведёт конвейер, и тот, кто будет переносить ревью в
> общие механизмы.

**Статус:** принято · **Дата:** 2026-09-09 · **Задача:** [#17](../../../issues/17)

## Контекст

Один и тот же шаг у соседей по семье решён по-разному, и разброс — тот самый,
ради которого заведён этот проект: у грейдера два файла на 78 и 69 строк, у
каталога один на 253. Задача [#17](../../../issues/17) требует не переносить
вслепую, а разобрать, чем они отличаются.

Форму спрашивают у соседа, а не помнят
([162](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/162-a-gap-asks-the-neighbours-first.md)) —
но у **обоих**: ни один из них не полон.

## Что различает образцы

| предмет | грейдер | каталог | берём |
|---|---|---|---|
| авто-ревью | `pull_request`, форк пропускается явно | то же | **обоих**, совпадают |
| ревью по обращению | есть: `issue_comment`, `issues`, гейт по `author_association` | **нет** | **грейдера** |
| группа отмены | без головы — прогон на старом коммите может вытеснить новый | **с головой** ([179](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/179-cancellation-group-must-name-the-head.md)) | **каталога** |
| ревью в защите ветки | стоит обязательной проверкой | не стоит, шаг `continue-on-error` | **каталога** |
| отсутствие секрета | не обработано | шаг с выводом `present`, предупреждение | **каталога** |
| версия действия | **закреплена по SHA** | по метке `@v1` | **грейдера** |
| источник промпта | плагин из плавающего маркетплейса | промпт в файле | **каталога** |
| набор инструментов агента | закрытый список чтения | закрытый список чтения и прогона | **обоих** |
| адресат находки | нет | `track_progress` ведёт комментарий | **каталога** |
| перенос находки после слияния | нет | есть, отдельный механизм | **не берём** |

## Решение

**Два файла, а не один.** Авто-ревью и ревью по обращению — разные механизмы с
разной поверхностью атаки: первый идёт сам на своём коде, второй запускается
текстом постороннего. Слить их в один файл значит смешать периметры.

**Версия действия закрепляется по SHA, а не по метке.** Здесь это не про дрейф,
а про доверие: действие получает токен и исполняет промпт, а подвижная метка
означает, что исполняемый код может смениться без нашего ведома
([152](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/152-pinning-callee-without-caller.md)).
SHA взяты у грейдера — те же, что уже проверены соседом.

**Плагин из маркетплейса не берём.** У грейдера промпт приходит плагином из
репозитория, закрепить который нечем: схема действия принимает только git-URL
без ревизии. Это осознанно принятый им остаточный риск. У нас промпт лежит в
файле — он и так наш, и версионируется вместе с деревом.

**Ревью не входит в защиту ветки.** Обязательная проверка одна — сводный гейт
([168](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/168-one-aggregating-required-check.md)),
а необязательный канал не задерживает основную работу
([084](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/084-best-effort-channels-never-block-the-main-path.md)).
Но находка ревью — отчёт о дефекте, а не мнение: она проверяется и чинится.

## Отвергнутые варианты

**Скопировать каталог целиком.** Отвергнуто: у него нет ревью по обращению и нет
закрепления по SHA, а перенос находок в задачу после слияния — отдельный
механизм, которому здесь пока не на чем стоять.

**Скопировать грейдер целиком.** Отвергнуто: группа отмены без головы — это
известный инцидент ([179](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/179-cancellation-group-must-name-the-head.md)),
ревью в обязательных проверках противоречит договору, а плавающий маркетплейс
добавляет риск, которого можно не брать.

**Отложить до выноса механизмов наружу (#2).** Отвергнуто: проект — свой первый
потребитель, и механизм, которым не пользуется автор, находит дыры на чужом
проекте ([155](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/155-a-template-you-dont-use-drifts.md)).

## Последствия

- в договор добавлен шаг «Ревью по обращению»: механизм, которого нет в
  таблице, — это механизм, о котором не договаривались;
- **изменение, правящее сам файл ревью, ревью не получает**: `track_progress`
  включает у действия режим, сверяющий файл прогона с версией на общей ветке.
  Цена принята сознательно, и знать о ней надо заранее — иначе одиннадцать
  секунд зелени читаются как удача;
- **перенос находки в задачу после слияния не сделан** и назван пробелом: пока
  изменение открыто, адресат находки — комментарий, после слияния адресата нет
  ([142](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/142-a-scheduled-red-needs-an-addressee.md));
- разнобой версии `actions/checkout` внутри проекта назван: в ревью она
  закреплена по SHA, в остальных прогонах — по метке `@v4`. Сводить их — работа
  выноса механизмов наружу, а не этой задачи.
