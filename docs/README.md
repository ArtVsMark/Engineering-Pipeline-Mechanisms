# Документы по читателю

> **Читатель:** любой, кто ищет нужный документ. Здесь только указатель:
> кому что читать. Содержание — в самих документах.

Документы делятся не по темам, а по читателю: каждому нужно своё, и одно из
другого не выводится
([021](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/021-split-docs-by-reader.md)).
Читатель документа объявлен в его первых строках, и указатель повторяет это
объявление, а не придумывает своё. У каждого предмета один канонический
документ; в остальных — ссылка на него
([022](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/022-one-canonical-document.md)).

## 🤖 Агенту — окну, которое работает в проекте

| Документ | Когда читать |
|---|---|
| [`AGENTS.md`](../AGENTS.md) | первым, при старте: что проект требует от любого агента |
| [`CLAUDE.md`](../CLAUDE.md) | вторым: чем агентское окно отличается от любого другого |
| [`roadmap.md`](roadmap.md) | когда выбираешь работу: порядок работ и признаки готовности |
| [`gaps.md`](gaps.md) | до того, как предполагать, что механизм работает: что ещё не доказано прогоном |
| [`roles.md`](roles.md) | когда отвечаешь от лица роли: вход, артефакт, запрет, предел |
| [`directions.md`](directions.md) | перед крупной работой: какие вопросы о продукте здесь задают |
| [`review.md`](review.md) | если ты внешний взгляд: процедура и роли захода |

## 🔧 Разработчику механизмов

| Документ | Когда читать |
|---|---|
| [`behaviour.md`](behaviour.md) | что происходит, когда: контуры, состояния, заморозка, путь взгляда |
| [`pipeline.md`](pipeline.md) | из чего конвейер состоит: шаги, файлы, правила формы |
| [`decisions/`](decisions/) | почему сделано так: к решению приходят по номеру из задачи, коммита или ответа |
| [`release.md`](release.md) | когда выпускаешь версию |

## 🧩 Соседу, который подключает механизмы к своему проекту

| Документ | Когда читать |
|---|---|
| [`README.md`](../README.md) | что это такое и стоит ли брать |
| [`onboarding.md`](onboarding.md) | когда уже решил брать: как подключиться |
| [`pipeline.md`](pipeline.md) | какие шаги и файлы приезжают к тебе |
| [`release.md`](release.md) | когда твой проект прибит к версии |

`pipeline.md` и `release.md` стоят у двух читателей: их объявленный читатель —
и тот, кто ведёт механизм, и тот, кто его подключает. Раскладка файлов по
подкаталогам читателя — отдельная работа
([#840](../../issues/840)).
