## 1.13.0

### Исправлено

### Гейт 162 не требует абзаца о семье от заготовки поставщика

Шаг `journal` (новый механизм называет, у кого из семьи спросили) судил
каждый механизм, который положил заход подключения, как написанный самим
проектом: на изменении подключения он отвергал 35 файлов поставщика, и
починить это можно было только правкой файла, который `--update` перепишет.
Теперь механизм, подписанный строкой лицензии чужого репозитория, и тонкий
вызов — прогон, где каждый джоб зовёт чужой переиспользуемый прогон, —
считаются подключёнными готовыми, и это печатается числом. Свои механизмы
гейт судит как прежде; если своё имя не узнать, не отпускается ничего.

#1743

### Перехват подъёма разбирает заголовок Dependabot с приставкой

Бот подстраивает заголовок под историю коммитов и пишет `build(deps): Bump …`.
Перехват ждал заголовок, начинающийся с `Bump`, и отказывал «не той формы»:
подъём не делался, сигнал висел красным. Теперь приставка
`<тип>(<область>)!: ` необязательна, групповой заголовок по-прежнему отвергается.

#1751

### Дрейф не записывает предупреждения прогонов самой площадки

Обновление Dependabot площадка запускает своим прогоном на `ubuntu-latest`, и
его предупреждение о переезде на Ubuntu 26 вставало записью `platform-warning`,
которую правкой дерева не снять: все `runs-on` уже `ubuntu-26.04`. Теперь
набор такого прогона (неперезапускаемый, у приложения действий) не судится, а
называется строкой вывода. Нового права токену не нужно.

#1753

### Хуки окна из заготовки чисты под ruff по умолчанию

Заход подключения кладёт потребителю хуки окна на Python
(`.claude/hooks/push_guard.py`, `bundle_hint.py`, `skill_log.py`). Под ruff 0.17
с настройками по умолчанию они давали три ошибки линта (`BLE001`, `PLW1510`) и
три файла под переформат, а без своего `include` шаг `lint` потребителя судит
и их — красное было о нашем коде. Теперь хуки чисты, лишний shebang снят (их
зовут через `python3`), и это держит тест.

#1744

### Предполётная потребителя не держит толчок на выключенной проверке

`bash .claude/preflight.sh` гоняет проверки так, как их прогонит площадка, но
класса из `.pipeline.yml` не читала: проверка, которую проект законно выключил
(`class: off` с причиной), краснела наравне с обязательной, и `--push` не
толкал никогда. Теперь красное выключенной проверки названо отдельной строкой
«не держит, класс off» и исход не красит. Ответ, который не прочитан, не
выключает ничего — это сказано, а не угадано.

Команда, стоящая и в выключенном, и в обязательном джобе, держит толчок:
выключенной она считается, только когда выключены все её записи. У
матричного джоба и у имени с `${{ }}` запись площадки с ответом не совпадёт,
и такой шаг считается обязательным — ошибка в сторону «держит».

#1745

### Сводка предполётной не считает выключенное красное прошедшим

Когда краснели только проверки класса `off`, предполётная писала «зелено: N
проверок дерева прошли», и в N входили упавшие. Теперь в число идут только
прошедшие. Имя записи `<джоб> / <вызванный>` предполётная собирает той же
функцией `pipeline_checks.composed`, что и разбор `.pipeline.yml`.

#1749

### Предполётная гоняет выбранные тесты, а не весь набор

Предполётная печатала выбор классификатора («тест-файлов: 101»), но дописывала
его в хвост строки `pytest` за `|| rc=$?`: тесты шли весь набор, а при красном
оболочка пыталась исполнить тест-файл как программу. Теперь выбор встаёт сразу
после `pytest`, и прогон перед толчком сужается так же, как в CI. Строка не
с `pytest ` выбор не принимает, и это сказано вслух.

#1749

### Страж толчка судит голову того дерева, которое толкают

Хук окна `push_guard` читал ветку в дереве проекта, и окно с двумя
репозиториями не могло толкнуть ветку `agent/…` второго. Теперь каталог
толчка ведётся по строке — каталог события, `cd`/`pushd`, `git -C`, `env -C`,
`cd` внутри `bash -c`; неузнанный (`cd -`, `popd`, `--git-dir`, `GIT_DIR=`) —
отказ с причиной. Закрыт и обход: `FOO=a/b git push origin main` страж не
узнавал толчком вовсе.

#1652

### Применение навыков — сырой записью на слитое изменение, общим шагом `step-skills.yml`

На каждом слитом изменении шаг дописывает в `.github/badges/skills.json` ветки `badges` проекта запись: какие навыки окна изменение ждало (по признакам `expected` в шапке каждого `SKILL.md`) и какие окно назвало строкой `Навык:` тела слитого коммита. Раз в неделю тот же шаг сводит записи — свои и соседей по семье — в блок живой задачи-аналитики: числом изменений, а не процентом. В поверхности новый шаг с одним джобом `skills`, заход сводки — входом `digest`; у навыка в шапке появился обязательный ключ `expected` — шаблоны путей и начала строк тела или `none — <причина>`; без него запись не собирается. Файл записей — словарём, а не построчно: его читает тот же читатель ветки `badges`, что факты соседей.

Хук окна `bundle_hint`: команда режет ветку `agent/…` (`git checkout -b|-B|--orphan`, `git switch -c|-C|--create|--force-create|--orphan`, `git worktree add -b|-B`, короткий ключ и слитно — `-bagent/x`, длинный ключ сокращением от четырёх знаков — `--orph`), а навык `bundle-the-work` в журнале вызовов этой сессии не значится — окно получает совет позвать его до первого коммита. #1664

### Карта гейтов семьи: правило × проект → чем держится, и три очереди

`scripts/family_gates.py` собирает по сводке каталога `where.json` карту: по каждому правилу и проекту семьи — чем правило держится. Исходов семь: наш механизм без переделки (вызов или копия), наш, переписанный к себе, наш с необъявленным видом взятия, свой механизм, прозой, никак, неприменимо.

Из карты выводятся три очереди кандидатов:

- доработать у нас — переписанное соседом;
- раздать в выпуске — свой гейт соседа там, где у нас нет машины;
- предложить каталогу — правило, которое машиной не держит никто.

Карта публикуется файлом `family-gates.json` на ветке `badges` тем же прогоном, что факты.

#1665

### Запись `feedback:` называет поставщика механизма

У записи раздела `feedback:` новое необязательное поле `supplier:` —
`владелец/репозиторий` поставщика механизма; без него запись адресована

Заход подключения пишет `.claude/kit-laid.json` — путь хука или навыка → имя

`python scripts/paths.py <ключ>` (у вас — `bash .claude/mechanisms.sh paths.py

#1623

### Страница выпуска несёт перепись отдачи

`scripts/portable_census.py` собирает раздел для страницы выпуска по переписи
`.rules/portable.json`. В разделе:

- счёт ответов по шкале с разницей против прошлого выпуска;

#1425

### Навык перезапуска окна и имя окна, собранное скриптом

Заход подключения кладёт навык `restart-the-window`: по решению владельца окно
толкает или называет ненатолкнутое, собирает имя нового окна, передаёт
основной контекст ссылками и снимает подписки на свои изменения. Имя окна
`[<окружение>] <проект> · <ДД.ММ>` собирает `scripts/window_name.py` —
у потребителя запускателем `.claude/mechanisms.sh`: краткое имя проекта

репозиторий — из `origin` клона. Проекта нет в таблице — имя не придумывается,
скрипт выходит исходом 3 и называет в stderr, куда дописать строку: stdout
несёт только имя. День в имени — по поясу владельца из той же таблицы, а не
по часам контейнера.
