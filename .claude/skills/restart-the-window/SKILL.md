# Перезапустить окно

> **Читатель:** окно, которому владелец сказал перезапуститься.

## Зачем это существует

Окно живёт три–пять дней
([006](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/006-window-lifetime.md)),
и имя окна начинается с окружения
([038](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/038-window-name-declares-its-environment.md)).
Срок и приставку правила называют, а **порядка перезапуска** — что толкнуть,
как назвать новое окно, что ему передать — не называют. Замер 26.10.2026:
окно механизмов прожило 5 суток 0 часов (шаг `window-lifetime` на #1700 и
#1702), перезапустило себя само, и порядок держался его памятью; в другом
проекте так не получилось (#1703).

Сперва спросили семью
([162](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/162-a-gap-asks-the-neighbours-first.md)):
у журнала прогресса механизмов окна нет вовсе — сверено его клоном
26.10.2026, — а у остальных соседей, по постановке владельца в #1703, такого
навыка ни у кого нет: перезапуск там держится памятью окна так же, как держался
здесь.

**Решает перезапуск человек.** Навык исполняет решение, а не принимает его:
без слова владельца окно не перезапускается, даже когда `window-lifetime`
красный.

## Что сделать

**1. До создания — ненатолкнутое толкнуто или названо.** Контейнер облачного
окна эфемерный: не отправленное в ветку пропадает вместе с ним.

```bash
git status -sb
git log --branches --not --remotes --oneline
```

Каждая ветка с работой толкается **предполётной**
(`python scripts/preflight.py --push`); толчок в обход неё — только по прямому
слову владельца, навык этого не разрешает сам. Что толкнуть нельзя (красное,
которое не успеть починить), — называется в стартовом сообщении строкой
«ветка такая-то не толкнута: почему».

**2. Имя нового окна — скриптом.**

```bash
python scripts/window_name.py --env WEB
```

`--env` — `WEB`, `LOCAL` или `CLI`: где будет работать **новое** окно. Краткое
имя проекта скрипт берёт из таблицы кратких имён у поставщика механизмов, а
репозиторий — из `origin` клона; дата — сегодняшняя. Исход `3` значит, что
проекта в таблице нет: имя не придумывается, а строка дописывается
поставщиком.

**3. Стартовое сообщение — ссылками, а не пересказом.** Пересказ прошлого и
есть то, от чего перезапуск лечит. Состав:

- **что читать первым** — ядро свода (`AGENTS.md`), затем свод окна;
- **откуда брать работу** — план работ или трекер, по порядку источников
  проекта;
- **открытые изменения окна** — номерами, с одной строкой о состоянии каждого
  (что красно и почему, если красно);
- **ветки, толкнутые без изменения**, и ненатолкнутые из шага 1;
- **решения дня** — номерами задач, в которых они записаны. Решения, ещё не
  записанного в задачу, в сообщении быть не должно: сперва запись, потом
  ссылка.

Отдельная задача-передача не заводится, если свод проекта её не требует:
трекер и есть передача.

**4. Создать окно.** Где есть инструмент сессий площадки — новое окно
создаётся им, с именем из шага 2 и сообщением из шага 3. Где его нет
(локальное окно, другая площадка) — имя и готовое стартовое сообщение
отдаются владельцу текстом: имя строкой для заголовка окна, сообщение — одним
блоком для вставки.

**5. После — подписки на свои изменения сняты.** Новое окно берёт их само;
два окна, подписанные на одно изменение, чинили бы его наперегонки.

## Чего этот навык НЕ делает

- **Не решает перезапуск** — решает владелец (006).
- **Не толкает в обход предполётной** — только по прямому слову владельца.
- **Не придумывает краткое имя** проекта, которого нет в таблице.
- **Не пересказывает** прошлое окно: всё, что новому окну нужно, — ссылкой в
  трекер или в дерево.
