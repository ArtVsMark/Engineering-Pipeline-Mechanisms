# Работа получает адрес раньше, чем её начинают

> **Читатель:** окно, в разговоре с которым только что родилась новая работа.

## Зачем это существует

Сборщик плана держит **выход**: строка без адреса — отказ сборки, снять
`- переделать бы доки` нечем. Но до выхода работа успевает родиться в
разговоре, прозвучать «ну давай ещё вот это» и остаться жить в памяти окна —
там, где её не видит ни план, ни долг, ни выпуск. Владелец сказал это прямо:
«под каждую задачу в любом случае заводится issue, мы же не накидываем работу
просто так».

**Замер 23.09.2026, за одну смену.** Окно завело тринадцать задач — все без
единой метки; заметил владелец, а не механизм (#655). В ту же смену две задачи
пришлось править задним числом: пункт «все четыре вызова» (их оказалось пять)
и пункт «пересборка по запросу» (к тому дню её вёл конвейер). И многострочные
пункты одной задачи (#646) отмечались трейлером только по первой строке —
остальное к пункту не относилось.

## Что сделать

**1. Задача — до кода и до строки плана.** Не «потом оформим»: без адреса
работу нечем снять, и она копится желанием
([154](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/154-none-must-name-its-reason.md)).

**2. Задача несёт то, по чему видно, что работа сделана:**

- **предмет** — что не так или чего нет, с замером, если он есть;
- **границы** — чего работа не делает;
- **приёмку пунктами** `- [ ] …`, **каждый в одну строку**: трейлер
  `Закрывает пункт:` сверяется с первой строкой пункта, и продолжение на
  следующей строке к пункту не относится;
- **метки**: зона (`area/*`), род (`bug` · `enhancement` · `documentation` ·
  `tech-debt` · `epic`) и сложность (`difficulty/*`). Без меток задачу не
  читает ни список, ни фильтр владельца.

Задача-заголовок адресом не является: снять её можно, а проверить нечем.

**3. Число в задаче — поиском по дереву, а не чтением двух файлов.** «Четыре
вызова» было прочитано в двух файлах прогона; пятый нашёл гейт. Считать —
командой, и команду назвать рядом.

**4. Чего задачей НЕ оформляют:**

- **мелкую правку по ходу** — её место в том изменении, где она встретилась;
- **находку внешнего взгляда** — её адрес уже есть, отпечаток в реестре #23, и
  второй адрес расщепил бы снятие;
- **живые задачи-адресаты** (реестры, план) — их ведёт механизм, и меток им не
  нужно.

**5. Решение владельца о задаче записывается в неё**, а не остаётся в
разговоре: место в плане, выбор между вариантами, отказ.

**6. Проверить себя сухим заходом сборщика:**

```bash
python scripts/work_plan.py      # без --apply; отказ по строке без адреса — работа занесена мимо задачи
```

## Чего этот навык НЕ делает

- **Не решает, нужна ли работа.** Он отвечает на «если делаем — где её
  адрес»; что делать, решает владелец.
- **Не кладёт работу в план.** Кладёт владелец; как — навык `work-the-plan`.
- **Не краснеет.** Выход держит сборщик плана, метки — счёт долга (#655);
  здесь — только момент, до которого гейт не дотягивается
  ([002](https://github.com/ArtVsMark/Engineering-Incidents-Playbook/blob/main/rules/ru/002-rule-without-mechanism.md)).
